## 2. 问题定义
### 背景现状
在传统教学场景中，学生完成学习任务的动力主要依赖外部压力（考试、家长督促），缺乏持续性的内在学习激励。同时，教师在管理学生作业、追踪学习进度方面耗费大量精力，缺乏有效的自动化工具。

### 核心痛点
1. **学生层面**：学习过程枯燥乏味，缺乏即时正向反馈，学习动力难以持续
2. **教师层面**：作业批改工作繁重，学情数据分散，难以快速掌握班级整体状态
3. **教学效果层面**：错题订正不及时、知识漏洞累积、学习效果难以量化

### 为什么做这个产品
通过引入"小组共同养虚拟宠物"的游戏化学习机制，将学习任务的完成与宠物的成长绑定，让学生在"养宠物"的内在动机驱动下主动完成学习任务，形成"学习→养好宠物→获得特权→更努力学习"的正向循环。

## 3. 目标

### 业务目标
- 建立以宠物养成与学习任务为核心的激励体系
- 实现"好好完成学习任务就能养好宠物"的强关联机制
- 构建清晰的班级、小组、个人三级学习激励结构

### 用户目标
| 角色 | 目标 |
|------|------|
| 教师 | 高效管理班级、减轻批改负担、及时掌握学情 |
| 学生 | 通过完成任务养好宠物、获得学习便利特权 |
| 小组 | 协作完成任务、共同承担宠物养成责任 |

### 技术目标
- 构建三端口（教师Web端、学生Web端、桌面宠物端）完整应用
- 实现宠物数据实时同步、任务状态跨端一致
- 保证系统稳定、安全、可扩展

## 4. 非目标
- **不包含**社交聊天功能（私聊、群聊均不在范围内）
- **不包含**在线视频课程或直播功能
- **不包含**第三方支付和真实货币交易
- **不包含**离线模式（桌面端在无网络时仅支持查看缓存数据）
- **不包含**硬件设备对接（智能笔、点读笔等）

## 5. 用户故事

### 教师用户故事
- 作为**老师**，我希望通过**生成班级邀请码**的方式，让**学生快速加入班级**，以便**简化学生注册流程**
- 作为**老师**，我希望能**创建多种类型的任务**（课后作业、课前预习、小组项目、课堂小测），并**设置截止时间和迟交扣分规则**，以便**全面管控学习流程**
- 作为**老师**，我希望能**在线批改学生作业**，并**一键将优秀作业公开展示**，以便**激励学生提升作业质量**
- 作为**老师**，我希望**自定义金币和成长值的奖惩规则**，并**设置宠物等级与学习特权的对应关系**，以便**灵活调整激励力度**
- 作为**老师**，我希望**一眼看清全班的作业提交率、平均分、每个小组和学生的学习情况**，以便**快速定位问题学生**
- 作为**老师**，我希望系统能**自动预警异常情况**（多次不交作业、成绩下滑、宠物状态差），以便**及时干预**

### 学生用户故事
- 作为**学生**，我希望能**用邀请码快速加入班级**，并**自动分配到对应小组**，以便**快速开始学习**
- 作为**学生**，我希望能**查看所有老师布置的任务、截止时间和提交要求**，并**在线提交作业**，以便**清晰管理学习任务**
- 作为**学生**，我希望能**查看小组宠物的等级、形象、成长值、健康值**，并用**金币购买食物、道具、装扮**，以便**参与宠物养成**
- 作为**学生**，我希望能**通过完成任务、拿优秀作业、课堂签到、帮同学解答问题、订正错题等多种方式赚取金币**，以便**有动力参与各种学习活动**
- 作为**学生**，我希望**错题和代码bug能变成虫子**，我**订正错题或修复bug就算捉虫成功**，以便**在纠错中获得额外奖励**
- 作为**学生**，我希望**70%的金币进入小组公共池养宠物，30%留给自己用**，以便**平衡个人与团队利益**

### 小组用户故事
- 作为**小组**，我们希望能**共同拥有和管理一只宠物**，共享成果、共担责任，以便**形成团队凝聚力**
- 作为**小组**，我们希望能**一起给小组任务分工**，并**汇总作业提交**，以便**高效完成小组任务**

### 桌面宠物端用户故事
- 作为**用户**，我希望**用自己的账号登录桌面端**，自动绑定小组宠物，**Web端数据实时同步**，以便**跨端体验一致**
- 作为**用户**，我希望能把**宠物拖放到桌面任意位置**，点它会有**互动反馈**，还**不挡其他操作**，以便**宠物成为真正的桌面伴侣**
- 作为**用户**，我希望**老师发新任务、作业快截止、批改完作业时能弹出气泡提醒**，以便**不会错过重要事项**
- 作为**用户**，我希望**任务逾期扣健康值时宠物会委屈提醒**，**宠物升级时有庆祝动画**，以便**奖惩有即时反馈**
- 作为**用户**，我希望**有错题或bug没改时宠物身上会出现虫子**，**修好后虫子立即消失**，以便**直观看到待办事项**
- 作为**用户**，我希望**右键点宠物能一键打开Web系统**，**鼠标悬停能看到金币和待办任务**，以便**快捷操作**

## 7. 验收标准

### 7.1 用户与认证模块
```
Given: 用户访问注册页面
When: 填写有效信息并提交
Then: 创建成功，返回登录页面，可使用新账号登录

Given: 学生持有班级邀请码
When: 输入邀请码并确认加入
Then: 自动分配到对应班级和小组，显示小组信息
```

### 7.2 任务管理模块
```
Given: 教师创建作业任务，设置截止时间为明天
When: 学生今天提交作业
Then: 作业正常提交，得分不受影响

Given: 学生逾期3天提交作业，迟交扣分规则为每天扣10%
When: 教师批改该作业
Then: 实际得分 = 作业得分 × (1 - 0.3) = 70%

Given: 教师打回作业要求重做
When: 学生重新提交
Then: 覆盖原提交，记录新的提交时间和内容
```

### 7.3 宠物养成模块
```
Given: 小组宠物当前等级1，成长值80
When: 小组完成一个任务获得30成长值
Then: 宠物成长值变为110，等级升为2

Given: 小组连续5天未完成任何任务
When: 健康值衰减规则为每天扣10点
Then: 宠物健康值变为50（初始100 - 5×10）

Given: 宠物等级达到5级
When: 解锁特权规则为"可查看答案解析"
Then: 该小组所有成员获得查看答案解析权限
```

### 7.4 金币经济模块
```
Given: 学生完成任务获得100金币奖励
When: 系统分配金币
Then: 个人账户获得30金币，小组公共池获得70金币

Given: 小组公共池有50金币，学生个人有20金币
When: 学生购买价值15金币的食物喂宠物
Then: 小组公共池扣除15金币，宠物健康值+10

Given: 学生个人金币为0，无法购买个人道具
When: 学生尝试购买需要10金币的道具
Then: 提示"金币不足"，购买失败
```

### 7.5 桌面宠物端
```
Given: 用户在Web端完成任务提交
When: 桌面端宠物数据同步
Then: 同步延迟不超过5秒，宠物界面更新

Given: 任务截止时间已过
When: 宠物主人未提交任务
Then: 桌面端弹出气泡提醒，显示扣健康值信息

Given: 学生有3道错题未订正
When: 打开桌面宠物端
Then: 宠物身上显示3只虫子图标
```

## 8. 约束条件

### 8.1 性能要求
| 指标 | 要求 |
|------|------|
| Web端页面响应时间 | 平均 < 2秒，95% < 3秒 |
| 桌面端数据同步延迟 | < 5秒 |
| API并发处理能力 | 支持同时在线500用户 |
| 数据库查询响应 | 简单查询 < 100ms，复杂查询 < 1s |

### 8.2 兼容性要求
| 平台 | 版本要求 |
|------|---------|
| Chrome | 最近2个版本 |
| Firefox | 最近2个版本 |
| Safari | 最近2个版本 |
| Edge | 最近2个版本 |
| Windows | Windows 10 及以上 |
| macOS | macOS 10.15 及以上 |

### 8.3 安全要求
| 类别 | 要求 |
|------|------|
| 密码存储 | bcrypt哈希加密 |
| 通信安全 | HTTPS全链路加密 |
| 权限控制 | RBAC角色权限模型 |
| 数据隔离 | 用户只能访问自己班级/小组数据 |
| 敏感信息 | 禁止明文日志、Token不暴露在URL |

### 8.4 业务限制
| 限制项 | 具体规则 |
|-------|---------|
| 班级人数 | 每个班级最多50名学生 |
| 小组人数 | 每组建议4-6人 |
| 任务截止 | 任务发布后截止时间可修改，迟交规则不可修改 |
| 金币余额 | 不允许为负数 |
| 健康值范围 | 0-100 |
| 宠物等级 | 1-99级 |

## 9. 风险与待确认问题

### 9.1 技术风险
| 风险 | 影响 | 应对措施 |
|------|------|---------|
| WebSocket长连接稳定性 | 桌面端同步可能中断 | 实现断线重连+消息队列补偿 |
| 多端数据一致性 | 三端数据可能短暂不一致 | 使用数据库事务+最终一致性 |
| 高并发下的金币计算 | 可能出现超发或扣错 | 使用分布式锁+幂等设计 |

### 9.2 业务风险
| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 学生刷金币行为 | 破坏激励体系平衡 | 增加行为检测+异常监控 |
| 小组分工不均 | 组员贡献度差异大 | 显示个人贡献度排名 |
| 宠物状态影响学习 | 过度关注宠物而非学习 | 宠物功能作为辅助，不与核心学分强挂钩 |

### 9.3 待确认问题
| # | 问题 | 状态 | 决策 |
|---|------|------|------|
| 1 | 迟交扣分比例是教师自定义还是系统固定？ | 待确认 | 建议教师可自定义 |
| 2 | 金币商城道具价格是否教师可调？ | 待确认 | 建议基础价格固定，教师可微调 |
| 3 | 学生能否退出当前小组？ | 待确认 | 建议需教师审批 |
| 4 | 桌面端是否需要开机自启？ | 待确认 | 建议默认关闭，用户可开启 |
| 5 | 宠物形象是否需要购买解锁？ | 待确认 | 建议等级解锁免费获得 |
